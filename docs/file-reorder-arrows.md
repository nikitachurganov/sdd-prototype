# Перемещение файлов стрелками в списке / таблице

## Назначение

Стрелки «Переместить выше» и «Переместить ниже» изменяют **ручной порядок** файлов на одну позицию. Действие выполняется для текущего выделения, применяется ко всему выделению атомарно и сохраняет относительный порядок выбранных файлов.

Документ фиксирует поведение для списка и табличного представления. Он не описывает перемещение файла в другую папку или изменение полей файла.

## Термины

- **Строка** — один файл в текущем ручном порядке.
- **Выделение** — все выбранные пользователем строки.
- **Блок выделения** — максимальная последовательность соседних выбранных строк. Например, для строк `2, 3, 6, 8, 9` блоками будут `2–3`, `6` и `8–9`.
- **Активная строка** — строка, на которой находится клавиатурный фокус. Она может входить в выделение из нескольких строк.
- **Набор сортировки** — полный набор строк, к которому применяется ручной порядок. В него не должны незаметно входить скрытые фильтром или не загруженные строки.

## Предусловия

Ручное перемещение доступно только когда выполнены все условия:

1. В списке есть хотя бы одна выбранная строка.
2. Активен режим ручного порядка; нет сортировки по имени, дате, размеру или другому полю.
3. Нет поиска, фильтра, группировки, пагинации или частичной загрузки, которые делают соседние позиции неоднозначными. Если продукт поддерживает упорядочивание в таких режимах, сервер должен однозначно определять соседей в полном наборе.
4. У пользователя есть право изменять порядок, а все выбранные строки доступны для перемещения.
5. Не выполняется другое сохранение или обновление порядка.

Если условие не выполнено, обе стрелки недоступны. Причина должна быть понятна из подсказки или пояснения рядом с контролом: например, «Чтобы изменить порядок, отключите сортировку по дате».

## Базовое действие

- `↑` перемещает выделение на одну строку выше.
- `↓` перемещает выделение на одну строку ниже.
- Перемещение не меняет порядок файлов **внутри** выделения.
- Если в выделении несколько блоков, каждый блок перемещается на одну строку одновременно. Порядок блоков также сохраняется.
- Операция атомарна: либо перемещаются все выбранные блоки, либо не перемещается ни один.

### Пример: одна строка

```text
1. A
2. B  ← выбрана
3. C

Нажатие ↑ → B, A, C
Нажатие ↓ → A, C, B
```

### Пример: непрерывный блок

```text
A, [B, C], D, E

Нажатие ↓ → A, D, [B, C], E
```

### Пример: разрозненное выделение

```text
A, [B], C, [D], E

Нажатие ↓ → A, C, [B], E, [D]
```

Здесь `B` и `D` не объединяются в один блок: каждый меняется местами со следующим невыбранным соседом. Выделенными после операции остаются те же файлы.

## Состояния стрелок

Пусть `N` — число строк в наборе сортировки, `min` — позиция первой выбранной строки, а `max` — позиция последней выбранной строки.

| Состояние | `↑` | `↓` |
|---|---|---|
| Нет строк (`N = 0`) | недоступна | недоступна |
| Нет выделения | недоступна | недоступна |
| Выбран единственный файл, `N = 1` | недоступна | недоступна |
| Выбран файл в первой строке | недоступна | доступна, если `N > 1` |
| Выбран файл в последней строке | доступна, если `N > 1` | недоступна |
| Выбран файл в середине | доступна | доступна |
| Выделен непрерывный блок, начинающийся в первой строке | недоступна | доступна, если после блока есть строка |
| Выделен непрерывный блок, заканчивающийся в последней строке | доступна, если перед блоком есть строка | недоступна |
| Выделены все строки | недоступна | недоступна |
| Выделено несколько блоков, и один из них касается верхней границы | недоступна | определяется по нижней границе |
| Выделено несколько блоков, и один из них касается нижней границы | определяется по верхней границе | недоступна |

Формально, при выполненных предусловиях:

```text
↑ доступна, если min > 1
↓ доступна, если max < N
```

Это правило исключает частичное перемещение разрозненного выделения. Например, при выборе строк `2` и `5` из пяти `↓` недоступна: строка `5` не может сдвинуться, поэтому строка `2` тоже не должна перемещаться отдельно.

## Алгоритм изменения порядка

1. Сформировать блоки выделения из соседних выбранных строк.
2. Проверить доступность направления и права на перемещение.
3. Для `↑` обрабатывать блоки сверху вниз; каждый блок меняется местами с одной невыбранной строкой непосредственно перед ним.
4. Для `↓` обрабатывать блоки снизу вверх; каждый блок меняется местами с одной невыбранной строкой непосредственно после него.
5. Сохранить новый порядок одним запросом / транзакцией.
6. Только после успешного ответа зафиксировать новый порядок или визуально подтвердить оптимистичное изменение.

Обработка в указанном порядке необходима, чтобы блоки не «перепрыгивали» друг через друга и не меняли взаимный порядок.

## Особые и ошибочные случаи

| Ситуация | Требуемое поведение |
|---|---|
| В выделении есть файл без права на перемещение | обе стрелки недоступны; текст причины: «В выделении есть файл, порядок которого нельзя менять». |
| Выбранный блок должен пересечь закреплённую / заблокированную строку | стрелка в этом направлении недоступна. Закреплённые строки образуют границу порядка. |
| Строка удалена или изменилась другим пользователем | обновить список; показать сообщение «Порядок изменился. Проверьте список и повторите действие». |
| Сохранение уже идёт | обе стрелки заблокированы, показывается индикатор выполнения; повторные нажатия не создают новые запросы. |
| Сохранение завершилось ошибкой | вернуть прежний порядок либо явно сохранить оптимистичный порядок как неподтверждённый; показать ошибку с действием «Повторить». |
| Конфликт версий порядка на сервере | не затирать чужое изменение; загрузить актуальный порядок и предложить пользователю повторить действие. |
| В таблице включили сортировку после выделения | снять доступность стрелок, но выделение не сбрасывать. |
| Виртуализированный список | перемещать можно только при наличии стабильного полного порядка на сервере; нельзя считать невидимые строки отсутствующими. |
| Пустой список | показать пустое состояние; стрелки не отображать или показывать отключёнными. |

## Выделение, фокус и прокрутка

- После успешного перемещения выбранными остаются те же файлы, включая разрозненное выделение.
- Активной остаётся тот же файл; фокус не должен «прыгать» на строку, с которой произошёл обмен.
- Если перемещённая активная строка выходит за видимую область, таблица / список прокручивается так, чтобы она оставалась видимой.
- При переключении между видом «список» и «таблица» сохраняются ручной порядок, выделение и доступность действий.

## Контролы и ввод

- Использовать две отдельные кнопки с иконками стрелок: «Переместить выше» и «Переместить ниже».
- У иконок должны быть доступные имена (`aria-label`): «Переместить выбранные файлы выше» и «Переместить выбранные файлы ниже».
- Если выбрано несколько файлов, в названии или подсказке указывать количество: «Переместить 3 файла выше».
- Отключённая кнопка имеет нативное состояние `disabled`, визуально отличается и объясняет причину через доступный текст / подсказку. Она не должна выглядеть активной.
- Кнопки доступны по `Tab`; `Enter` и `Space` запускают действие. Дополнительно можно поддержать `Alt + ↑` и `Alt + ↓`, если фокус находится в списке, а пользователь не редактирует текстовое поле.
- Горячие клавиши не заменяют видимые кнопки и не должны конфликтовать с системной навигацией или скринридером.
- После выполнения действия экранный диктор получает ненавязчивое сообщение: «Перемещено выше: 3 файла. Новые позиции: 4–6».

## Визуальная обратная связь

- Нажатие даёт мгновенный pressed-state; перемещаемые строки могут плавно сместиться на 150–300 мс без изменения размеров строк.
- При настройке уменьшения движения (`prefers-reduced-motion`) перемещение показывается без анимации или с минимальным затуханием.
- После успешного сохранения показать краткое уведомление: «Файл перемещён выше» или «Перемещено ниже: 3 файла». Уведомление не перехватывает фокус.
- Если операция обратима, в уведомлении доступно действие «Отменить». Оно возвращает порядок, актуальный непосредственно до последнего перемещения.

## Приёмочные сценарии

| № | Начальный порядок и выделение | Действие | Ожидаемый результат |
|---:|---|---|---|
| 1 | `A, [B], C` | `↑` | `[B], A, C`; `↑` становится недоступной. |
| 2 | `A, [B], C` | `↓` | `A, C, [B]`; `↓` становится недоступной. |
| 3 | `[A], B, C` | `↑` | Ничего не происходит: кнопка недоступна. |
| 4 | `A, B, [C]` | `↓` | Ничего не происходит: кнопка недоступна. |
| 5 | `A, [B, C], D, E` | `↓` | `A, D, [B, C], E`; порядок `B, C` сохранён. |
| 6 | `A, [B], C, [D], E` | `↑` | `[B], A, [D], C, E`; оба блока сдвинуты одновременно. |
| 7 | `A, [B], C, [D], E` | `↓` | `A, C, [B], E, [D]`; оба блока сдвинуты одновременно. |
| 8 | `A, [B], C, D, [E]` | `↓` | Действие недоступно: нижний блок уже на границе. |
| 9 | `[A, B, C]` | `↑` или `↓` | Обе кнопки недоступны. |
| 10 | `A, [B]`, включена сортировка по дате | `↑` или `↓` | Действие недоступно с пояснением о сортировке. |
| 11 | `A, [B], C`, сервер возвращает ошибку | `↑` | Отображается ошибка и восстанавливается / помечается неподтверждённый исходный порядок согласно выбранной стратегии. |

## Решение, которое требуется от продукта

Настоящая спецификация использует строгую атомарную модель: если хотя бы один выбранный блок нельзя сдвинуть, стрелка недоступна для всего выделения. Это исключает неочевидную ситуацию, в которой часть выбранных файлов сместилась, а часть осталась на месте. Если продукту нужна другая модель (например, перемещать только блоки, не дошедшие до границы), её следует оформить как отдельное поведение с явным сообщением пользователю.
